# Sales CRM (Deals, Tasks, Reports) in MyDesk — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-account «المبيعات» group in MyDesk with Deals, Tasks, Sales reports and Sales settings, stored in MyDesk's own Postgres, plus a conversation/contact panel section and a Super Admin overview.

**Architecture:** Six `crm_*` tables scoped by `account_id`; small `SalesCrm::` service objects (one operation each, transactional, writing an activity row and broadcasting over ActionCable); Pundit policies; a `sales_crm` account feature flag; JSON API under `api/v1/accounts/:id/crm`; Vue 3 pages under `routes/dashboard/crm`. Core Chatwoot files are touched in ~12 marked places only, documented in `docs/mydesk/sales-crm-core-touchpoints.md`.

**Tech Stack:** Rails 7.1, Pundit, Sidekiq + sidekiq-cron, ActionCable, Vue 3 Composition API, Vuex (existing store), vuedraggable 4, `@chatwoot/viz` charts, RSpec + FactoryBot, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-31-sales-crm-design.md` (Arabic; binding).

## Global Constraints

- Namespace `SalesCrm::` for Ruby (`Crm::` is Chatwoot's LeadSquared code). Tables `crm_pipelines, crm_stages, crm_deals, crm_tasks, crm_notes, crm_activities`. `SalesCrm.table_name_prefix = 'crm_'` already exists in `app/models/sales_crm.rb`.
- Every new file starts with a `# Custom (MyDesk)` / `// Custom (MyDesk)` / `<!-- Custom (MyDesk) -->` comment. Every edit to a core file is marked on the line/block.
- Amounts are `amount_cents` bigint (halalas); API exposes `amount` as decimal string with 2 places and accepts decimal or Arabic-Indic digits.
- Default pipeline «المبيعات», currency `SAR`, stages (name, probability, kind, color): عميل محتمل 10 open `#94a3b8`; مؤهل 25 open `#60a5fa`; تم إرسال العرض 50 open `#a78bfa`; تفاوض 75 open `#f59e0b`; مكسوبة 100 won `#22c55e`; خاسرة 0 lost `#ef4444`.
- Expected value = Σ amount_cents × probability / 100 over open deals of one pipeline (integer division at the end).
- Time zone for today/overdue: `account.reporting_timezone.presence || 'Asia/Riyadh'`.
- Notification type `crm_task_due: 20`.
- API error shapes: 403 `{ error: 'crm_disabled' }`, 404 for other-account or hidden records, 409 `{ error: 'stale' }`, 422 `{ message: <translated> }`.
- All UI text in `crm.json` (ar, en) and `config/locales/sales_crm.{ar,en}.yml`; a spec asserts key parity.
- CSS: logical properties only (`ms-/me-/ps-/pe-/start/end`).
- Specs run as `docker compose exec -T -e RAILS_ENV=test rails bundle exec rspec <paths>`; Vitest as `docker compose exec -T rails pnpm test -- <paths>` (check `package.json` `test` script once in Task 10 and use what it defines).
- Run `db:migrate` with `ANNOTATERB_SKIP_ON_DB_TASKS=1` to avoid rewriting unrelated model comments.
- Git: stage only; the user commits on request. Commit message footer: `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **Cross-account access:** any `crm/*` endpoint with another account's deal/task/pipeline id must 404; agent with `crm_agents_see_own_deals_only` must not see others' deals. Tests: Task 7 `cannot read another account's deal`, Task 4 `agent scope hides others' deals`.
2. **Drag to lost without reason / failed move:** 422 and the card snaps back. Tests: Task 3 `move to lost requires lost_reason`, Task 11 `moveDeal reverts on failure`.
3. **Stage/pipeline deletion with deals:** 422 unless target given; deals moved atomically. Tests: Task 3 `remove stage moves deals`, `remove stage without target raises`.
4. **Reminders:** one per task, none twice, no crash without conversation, computed in account tz. Tests: Task 8.
5. **Concurrent edits:** stale `lock_version` → 409, UI reloads. Tests: Task 3 `stale update raises`, Task 7 `409 stale`.

### Task 3: Deal and pipeline services

**Files:** `services/sales_crm/deals/{create,update,move,reopen,discard,restore,search}.rb`, `pipelines/{create,update,destroy}.rb`, `forecast.rb`.
**Tests:** `spec/services/sales_crm/deals/*_spec.rb`, `pipelines/*_spec.rb`, `forecast_spec.rb`.

**Interfaces (Produces):** every service `new(account:, user:, **params).perform -> record` and raises `SalesCrm::ValidationError` (message = `I18n.t('sales_crm.errors.…')`) or `ActiveRecord::StaleObjectError`.
- `Deals::Create(params: {title, amount, pipeline_id, stage_id, contact_id, assignee_id, close_date, notes, conversation_id, source})` → sets `contact_name_snapshot`, `currency` from pipeline, `position` = max+1 in stage, status from stage kind, logs `created`, broadcasts.
- `Deals::Update(deal, params incl. lock_version)` → logs `amount_changed`/`assignee_changed` when changed.
- `Deals::Move(deal, stage_id:, position:, lost_reason: nil, lock_version:)` → reorders siblings (single `UPDATE … position = position + 1 WHERE …`), sets status/won_at/lost_at, requires `lost_reason` for lost (`errors.lost_reason_required`), logs `stage_changed`/`won`/`lost`.
- `Deals::Reopen(deal)` → first open stage, clears won/lost, logs `reopened`.
- `Deals::Discard(deal)`, `Deals::Restore(deal)`.
- `Deals::Search(pipeline_id:, stage_id:, assignee_id:, status:, q:, scope: :board|:table, page:)` → `{ deals: Relation, counts: {stage_id => {count, total_cents}} }`; board = first 100 per stage ordered by position; `q` matches `title_normalized ILIKE %q%` or `contact_name_normalized`.
- `Pipelines::Update(pipeline, name:, currency:, stages: [{id?, name, probability, kind, color, position}], stage_moves: {removed_stage_id => target_stage_id})` → transaction; removed stage with deals and no target → `errors.stage_has_deals`; currency change with deals → `errors.currency_locked`.
- `Pipelines::Destroy(pipeline)` → `errors.last_pipeline` / `errors.pipeline_has_deals`.
- `Forecast.call(account:, pipeline:, assignee_id: nil) -> {open_count, open_total_cents, expected_cents, won_total_cents, lost_total_cents, currency}` in one SQL.
