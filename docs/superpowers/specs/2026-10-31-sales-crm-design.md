# مواصفات: المبيعات (CRM) داخل MyDesk — الصفقات والمهام والتقارير

التاريخ: 2026-10-31 · الحالة: معتمدة من المستخدم (تحل محل مواصفات Twenty الملغاة)

## 1. الهدف

مجموعة **«المبيعات»** في MyDesk يفعّلها مدير المنصة لكل تاجر، وفيها الصفقات والمهام وإعدادات المبيعات وتقارير المبيعات، مع قسم «الصفقات والمهام» داخل المحادثة وصفحة العميل. كل البيانات في قاعدة MyDesk، بلا خدمة خارجية.

**معيار النجاح:**
- موظف التاجر ينشئ صفقة من لوحة الصفقات أو من داخل المحادثة، وينقلها بين المراحل بالسحب، ويخسرها بسبب، ويكسبها.
- ينشئ مهمة بموعد فيصله تنبيه في الجرس والجوال عند حلوله، ويرى عدّاد المتأخرة.
- المدير يرى التقارير الأساسية ويعدّل المسارات.
- تاجر لا يرى بيانات تاجر آخر مهما حاول.
- مدير المنصة يفعّل الميزة لكل تاجر ويرى صفقات كل التجار.
- كل شاشة بالعربية والإنجليزية بجودة واحدة.

**قرارات المستخدم:** البناء داخل MyDesk بدل Twenty؛ التقارير الأساسية في النسخة الأولى؛ ترتيب أقسام المبيعات: نظرة عامة (لاحقاً)، الصفقات، المهام، الشركات (لاحقاً)، عروض الأسعار (لاحقاً)، تقارير المبيعات، إعدادات المبيعات.

## 2. خارج النطاق (النسخة الأولى)

نظرة عامة، والشركات، وعروض الأسعار، وصفقات سلة التلقائية، والأتمتة، والحقول المخصصة للصفقات، والمرفقات على الصفقة، وتحويل العملات، وتقارير Super Admin عبر التجار، واقتراحات المساعد الذكي، وتضمين الـ CRM في تصدير بيانات الحساب. حقل «المصدر» على الصفقة جاهز من الآن لصفقات سلة.

## 3. البيانات

كل الجداول بـ `account_id` غير فارغ ومفاتيح أجنبية. الأسماء بادئتها `crm_`، والكود تحت `SalesCrm::` (لأن `Crm::` محجوز في Chatwoot لتكامل LeadSquared).

| الجدول | الأعمدة الأساسية | القيود |
|---|---|---|
| `crm_pipelines` | account_id, name, currency (ISO 4217، افتراضي SAR), position | اسم فريد داخل الحساب |
| `crm_stages` | account_id, pipeline_id, name, probability (0–100), kind (open/won/lost), position, color | `CHECK probability BETWEEN 0 AND 100`؛ فهرس فريد جزئي: مرحلة `won` واحدة و`lost` واحدة لكل مسار |
| `crm_deals` | account_id, pipeline_id, stage_id, contact_id (قد يكون فارغاً), contact_name_snapshot, assignee_id, creator_id, conversation_id, title, amount_cents (bigint ≥ 0), currency, close_date, status (open/won/lost), won_at, lost_at, lost_reason, source (manual/conversation/salla), position, notes, lock_version, discarded_at | `CHECK amount_cents >= 0`؛ status يُشتق من نوع المرحلة ويُحفظ للاستعلام |
| `crm_tasks` | account_id, title, description, due_at, status (open/done), done_at, assignee_id, creator_id, contact_id, deal_id, conversation_id, reminded_at | حذف الصفقة يُفرغ deal_id ولا يحذف المهمة |
| `crm_notes` | account_id, deal_id, user_id, content | تُحذف مع الصفقة |
| `crm_activities` | account_id, deal_id, user_id (قد يكون فارغاً للنظام), kind, data (jsonb), created_at | تُكتب تلقائياً، لا تُعدَّل. الأنواع: created, stage_changed, amount_changed, assignee_changed, won, lost, reopened, note_added, task_added, task_done, restored |

**الفهارس:** deals (account_id, pipeline_id, stage_id, position)، (account_id, contact_id)، (account_id, assignee_id, status)، (account_id, status, won_at)، (account_id, status, lost_at)، (account_id, close_date)؛ tasks (account_id, assignee_id, status, due_at)، (account_id, deal_id)، (account_id, contact_id)، (status, due_at, reminded_at) للتنبيهات؛ activities (account_id, deal_id, created_at)؛ stages (pipeline_id, position).

**الحذف الناعم:** الصفقات فقط (`discarded_at`)، تُستعاد من الجدول خلال 30 يوماً، ثم تُحذف نهائياً بمهمة يومية. المهام والملاحظات حذف عادي.

**إعدادات الحساب** (في `accounts.settings` الموجود): `crm_agents_see_own_deals_only` (افتراضي false)، `crm_default_currency` (افتراضي SAR).

**التفعيل لكل تاجر:** علم ميزة Chatwoot `sales_crm` في `config/features.yml` (عمود `feature_flags_ext_1`، يُضاف في آخر القائمة، معلَّم). يظهر في صفحة الحساب في Super Admin تلقائياً، ويُفحص بـ `account.feature_enabled?('sales_crm')`.

**ما نعيد استخدامه من Chatwoot:** العملاء، والموظفون وأدوارهم، وPundit، والإشعارات، وActionCable، والمنطقة الزمنية `reporting_timezone`، وعلم الميزات، والرسوم البيانية `@chatwoot/viz`.

## 4. الخادم

### 4.1 الخدمات (`app/services/sales_crm/`)

كل خدمة تستقبل `account:` و`user:` وتعمل داخل معاملة واحدة، وتكتب سجل النشاط وتبث حدث ActionCable:

- `Deals::Create`, `Deals::Update`, `Deals::Move` (مرحلة + ترتيب؛ تطلب `lost_reason` عند مرحلة lost؛ تضبط status/won_at/lost_at)، `Deals::Reopen` (إلى أول مرحلة مفتوحة)، `Deals::Discard`, `Deals::Restore`, `Deals::Search` (الفلاتر والبحث المطبَّع).
- `Tasks::Create`, `Tasks::Update`, `Tasks::Complete`, `Tasks::Reopen`, `Tasks::Destroy`, `Tasks::List` (النطاقات بمنطقة وقت الحساب).
- `Pipelines::Create`, `Pipelines::Update` (مع `stage_moves` لنقل صفقات مرحلة محذوفة)، `Pipelines::Destroy` (مرفوض إن كان الوحيد أو فيه صفقات)، `Pipelines::EnsureDefault` (المسار «المبيعات» بالمراحل: عميل محتمل 10%، مؤهل 25%، تم إرسال العرض 50%، تفاوض 75%، مكسوبة 100%، خاسرة 0%).
- `Forecast` : `{ open_count, open_total_cents, expected_cents, won_total_cents, lost_total_cents, currency }` باستعلام SQL واحد؛ المتوقع = Σ amount × probability / 100 للمفتوحة.
- `Reports::Summary`, `Reports::Funnel`, `Reports::Agents`, `Reports::LostReasons`, `Reports::Timeline`, `Reports::Export` (CSV).
- `Normalize.text` للبحث: إزالة التشكيل والتطويل، توحيد أإآ→ا، ة→ه، ى→ي، تحويل الأرقام العربية، حروف صغيرة. يُخزَّن عمود `title_normalized` و`contact_name_normalized` في الصفقات لفهرسة البحث.

### 4.2 الصلاحيات (Pundit)

`DealPolicy`, `TaskPolicy`, `PipelinePolicy`, `ReportPolicy`:
- المدير: كل شيء.
- الموظف: يرى ويعدّل الصفقات كلها، أو صفقاته فقط عند تفعيل `crm_agents_see_own_deals_only`؛ لا يعدّل المسارات ولا الإعدادات؛ يحذف فقط صفقاته.
- المهام: الموظف يرى الكل ويُنجز مهامه ومهام غيره، ويحذف ما أنشأه.
- التقارير: المدير كل الأرقام؛ الموظف أرقامه فقط.

### 4.3 الأحداث والمستمعون

- **دمج عميلين:** `SalesCrm::ContactMergePatch` يُدرج بـ `prepend` في `ContactMergeAction` من `config/initializers/sales_crm.rb` (بدون تعديل الملف الأصلي): تنتقل الصفقات والمهام للعميل الباقي.
- **حذف عميل:** `contact_id` يصبح فارغاً وتبقى `contact_name_snapshot`.
- **إزالة موظف من الحساب:** تُدرج خطوة في `Agents::DestroyJob` بنفس أسلوب الـ prepend: صفقاته ومهامه المفتوحة تصبح بلا مسؤول.
- **حذف الحساب:** `dependent: :delete_all` على كل الجداول.
- **بث فوري:** `SalesCrmListener` يبث `crm.deal_created/updated/moved/discarded` و`crm.task_created/updated` لقناة الحساب عبر `ActionCableListener` نفسه (إضافة معلَّمة) أو مستمع منفصل مشترك في الـ dispatcher.

### 4.4 التنبيهات

- نوع إشعار `crm_task_due: 20` (موضع بت؛ بعيد عن أنواع Chatwoot القادمة) في `Notification::NOTIFICATION_TYPES` مع فرع العنوان: «موعد مهمة: {العنوان}».
- `SalesCrm::TaskReminderJob` كل 5 دقائق عبر `config/schedule.yml`: المهام المفتوحة ذات `due_at <= now` و`reminded_at IS NULL`، تنبيه واحد للمسؤول عبر الجرس والدفع، ثم `reminded_at = now`.
- الكائن الأساسي للإشعار: محادثة المهمة إن وُجدت، وإلا آخر محادثة للعميل، وإلا يُنشأ الإشعار بكائن أساسي هو المهمة نفسها إذا سمح `Notification` بذلك (يُتحقق في الخطة؛ البديل: عدّاد المتأخرة فقط).
- البريد خارج النسخة الأولى.

### 4.5 الواجهة البرمجية (`api/v1/accounts/:account_id/crm/`)

كلها تتطلب علم `sales_crm` مفعّلاً وإلا `403 { error: 'crm_disabled' }`:

| المسار | الصلاحية |
|---|---|
| `GET status` → `{ enabled, overdue_count, is_admin, settings }` | الكل (يرجع `enabled:false` بدل 403) |
| `pipelines` index/create/update/destroy | الكتابة للمدير |
| `deals` index (فلاتر: pipeline_id, stage_id, assignee_id, status, q؛ ترقيم 100 لكل مرحلة في عرض اللوحة، 50 للجدول) / show / create / update / destroy / `PATCH :id/move` / `POST :id/reopen` / `POST :id/restore` / `GET :id/activities` / `notes` index+create+destroy | حسب السياسة |
| `GET deals/forecast` | الكل (مقيد بالموظف عند الإعداد) |
| `tasks` index (scope: mine/today/overdue/upcoming/done/all + contact_id/deal_id) / create / update / destroy / `POST :id/complete` / `POST :id/reopen` | حسب السياسة |
| `GET contacts/:contact_id/summary` → صفقات مفتوحة + مهام قادمة | الكل |
| `reports/summary|funnel|agents|lost_reasons|timeline` (params: from, to, pipeline_id, assignee_id, interval) و`GET reports/export.csv` | المدير؛ الموظف أرقامه |
| `settings` show/update | المدير |

الأخطاء: `422 { message }` برسالة مترجمة؛ `409 { error: 'stale' }` عند تضارب `lock_version`.

### 4.6 Super Admin

صفحة مستقلة «CRM» (`super_admin/crm_overview`): جدول كل الحسابات مع حالة الميزة وعدد الصفقات والمهام، ورابط لتفعيلها من صفحة الحساب؛ و«صفقات كل التجار» بفلاتر (الحساب، الحالة، الفترة) وإجماليات لكل حساب، للقراءة فقط، وكل فتح يُسجَّل في سجل Rails بسطر `[CRM audit]`.

## 5. الواجهة

### 5.1 القائمة الجانبية

مجموعة «المبيعات» (أيقونة `i-lucide-briefcase`) بعد العملاء، تظهر فقط عند `sales_crm` مفعّل. الأقسام الظاهرة في النسخة الأولى بترتيب ثابت: **الصفقات**، **المهام** (شارة المتأخرة)، **تقارير المبيعات** (المدير، والموظف يرى تقاريره)، **إعدادات المبيعات** (المدير). مواضع نظرة عامة/الشركات/عروض الأسعار محجوزة ولا تُعرض.

### 5.2 الصفقات (`/app/accounts/:id/crm/deals`)

- الرأس: «الصفقات» + «تتبّع كل صفقة محتملة من أول تواصل حتى الفوز أو الخسارة.»؛ أزرار: صفقة جديدة، تعديل المسار (المدير)، تبديل لوحة/جدول، تصدير CSV.
- الفلاتر: المسار، والمسؤول («أي مسؤول»)، والحالة (مفتوحة/مكسوبة/خاسرة/الكل)، والبحث.
- الملخص: «N مفتوحة · المجموع · المتوقع» بعملة المسار.
- اللوحة: عمود لكل مرحلة (الاسم، العدد، المجموع، النسبة، لون المرحلة)؛ بطاقة: العنوان، المبلغ، العميل، التاريخ، المسؤول؛ سحب وإفلات بين الأعمدة وداخلها (`vuedraggable`) بتحديث متفائل وتراجع عند الفشل؛ الإفلات في «خاسرة» يفتح نافذة السبب (إلزامي)؛ 100 بطاقة ثم «عرض المزيد»؛ «+ إضافة صفقة» أسفل كل عمود.
- الجدول: أعمدة قابلة للفرز، ترقيم 50.
- نموذج الصفقة (لوحة جانبية): العنوان (إلزامي، حتى 200 حرف)، المبلغ (يقبل أرقاماً عربية)، العملة (من المسار)، المرحلة، العميل (بحث في عملاء Chatwoot، اختياري)، المسؤول، تاريخ الإغلاق المتوقع (تحذير إن كان في الماضي)، ملاحظات.
- صفحة التفاصيل: الحقول قابلة للتعديل، أزرار فوز/خسارة/إعادة فتح/حذف، المهام مع إضافة، الملاحظات، سجل النشاط، رابط محادثات العميل. عند `409 stale`: «تغيّرت الصفقة، حدّث الصفحة».
- المحذوفة: تبويب «المحذوفة» في الجدول مع استعادة (المدير).

### 5.3 المهام (`/crm/tasks`)

تبويبات: مهامي، اليوم، المتأخرة، القادمة، المنجزة، الكل (المدير). الصف: مربع الإنجاز، العنوان، الموعد (أحمر إن تأخر)، العميل/الصفقة كروابط، المسؤول. نموذج: العنوان، الوصف، الموعد (تاريخ ووقت بمنطقة الحساب)، المسؤول، ربط اختياري بعميل أو صفقة. شارة المتأخرة تُحدَّث بعد كل إنجاز وعبر البث الفوري.

### 5.4 تقارير المبيعات (`/crm/reports`)

فلاتر: الفترة (اليوم/الأسبوع/الشهر/الربع/مخصصة)، المسار، الموظف. الأقسام:
1. **ملخص:** بطاقات المفتوح، المتوقع، المكسوب، الخاسر، نسبة الفوز، متوسط قيمة الصفقة، متوسط أيام الإغلاق؛ كل بطاقة مع مقارنة بالفترة السابقة.
2. **قمع التحويل:** عدد الصفقات التي مرّت بكل مرحلة ونسبة الانتقال (من سجل النشاط `stage_changed` + الإنشاء).
3. **أداء الموظفين:** جدول قابل للفرز.
4. **أسباب الخسارة:** الأسباب مجمّعة (بعد التطبيع) بالعدد والقيمة.
5. **المبيعات عبر الزمن:** رسم خطي (جديد/مكسوب/خاسر) بفاصل يوم/أسبوع/شهر.
6. تصدير CSV للفترة.

### 5.5 داخل المحادثة وصفحة العميل

قسم «الصفقات والمهام» في `ContactPanel` (المحادثة) وفي لوحة العميل (صفحة العملاء) بنفس المكوّن: الصفقات المفتوحة (العنوان، المرحلة، المبلغ)، المهام القادمة مع مربع إنجاز، زرا «صفقة جديدة» و«مهمة جديدة» يعبّئان العميل والمسؤول (المسند للمحادثة) والمحادثة الأصل. يظهر فقط عند تفعيل الميزة.

### 5.6 إعدادات المبيعات (`/crm/settings`، المدير)

محرر المسارات: إضافة مسار، تسمية، العملة (تُقفل بعد وجود صفقات)، المراحل بالسحب مع الاسم والنسبة واللون والنوع، حذف مرحلة فيها صفقات يطلب مرحلة بديلة، حذف مسار يُرفض إن كان الوحيد أو فيه صفقات. مفتاح «الموظف يرى صفقاته فقط». العملة الافتراضية للمسارات الجديدة.

## 6. اللغتان

- كل النصوص في `app/javascript/dashboard/i18n/locale/{ar,en}/crm.json` وملفات `config/locales/sales_crm.{ar,en}.yml`. اختبار يتأكد من تطابق المفاتيح بين اللغتين.
- الاتجاه بخصائص CSS منطقية فقط؛ لا `left/right`.
- الأرقام والعملات بـ `Intl.NumberFormat(locale, { style: 'currency' })`؛ التواريخ والأوقات النسبية بأدوات Chatwoot الموجودة؛ الوقت المطلق بمنطقة الحساب.
- الجموع العربية بمفاتيح صريحة (`zero/one/two/few/many/other`) في `crm.json` ودالة مساعدة `crmPlural(count, key)`؛ الإنجليزية one/other.
- حقل المبلغ يقبل الأرقام العربية الهندية ويحوّلها.
- رسائل الخادم بـ `I18n.t` حسب لغة المستخدم.

## 7. الحالات الخاصة (كلها مختبَرة)

| الحالة | السلوك |
|---|---|
| نقل إلى «خاسرة» بلا سبب | 422 ورسالة؛ الواجهة تطلب السبب قبل الإرسال |
| حذف مرحلة فيها صفقات بلا بديل | 422 |
| حذف المسار الوحيد، أو مسار فيه صفقات | 422 |
| تغيير عملة مسار فيه صفقات | 422 |
| إعادة فتح مكسوبة/خاسرة | تعود لأول مرحلة مفتوحة، status=open، تُمسح won_at/lost_at، ويُسجَّل `reopened` |
| تعديل متزامن | 409 stale؛ الواجهة تعرض تنبيهاً وتعيد التحميل |
| سحب فشل | البطاقة تعود لمكانها الأصلي ورسالة خطأ |
| عميل دُمج | الصفقات والمهام للعميل الباقي |
| عميل حُذف | contact_id فارغ، الاسم من اللقطة |
| موظف أُزيل | صفقاته ومهامه المفتوحة بلا مسؤول، تظهر للمدير بفلتر «بدون مسؤول» |
| صفقة حُذفت ولها مهام | المهام تبقى بدون صفقة |
| مهمة بلا موعد | لا تنبيه، لا تظهر في اليوم/المتأخرة |
| «اليوم» و«المتأخرة» | بمنطقة `reporting_timezone` للحساب أو Asia/Riyadh |
| تنبيه مكرر | مستحيل: `reminded_at` يُضبط في نفس المعاملة |
| مبلغ سالب أو > 10^13 هللة | 422 |
| تاريخ إغلاق في الماضي | مسموح مع تحذير في الواجهة |
| حساب غير مفعّل | 403 crm_disabled؛ لا تظهر المجموعة |
| وصول لصفقة حساب آخر | 404 (الاستعلام من `Current.account`) |
| موظف مع «صفقاته فقط» | يرى/يعدّل/ينقل صفقاته فقط؛ غيرها 404 |
| 10,000 صفقة في مرحلة | اللوحة تعرض 100 + عرض المزيد؛ العدادات من SQL |
| بحث «احمد» يجد «أحمد» | عبر الأعمدة المطبَّعة |

## 8. الجودة والفصل

- TDD: RSpec (نماذج، خدمات، سياسات، طلبات) + Vitest (المتاجر، التنسيق، المكوّنات الرئيسية).
- Rubocop وESLint بلا مخالفات على الملفات الجديدة.
